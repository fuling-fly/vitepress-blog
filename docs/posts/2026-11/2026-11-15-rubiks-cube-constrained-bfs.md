# 手写魔方层先法总出错，我改成带约束的 BFS

我在写一个 3×3 魔方求解器，Python 做核心，后面还要接一个 Web 界面，并同步一份 Java 版。我以为层先法是最省事的：白十字、白角、第二层，每块枚举 12 个位置乘 2 种朝向，写 if 分支就行。真正跑起来，白十字在一条普通打乱上直接死循环。

## 先说结论

把「这一步该用哪个公式」换成「把这块送到这个位置，已经放好的块不许动」，然后让带约束的搜索去找步数。手写分支代码短，但正确性靠人肉穷举；搜索版本代码也短，而且不会漏。

- 每放一块，只把这一块自己的贴纸位置、以及已放好块的贴纸位置组成状态，BFS 一层层推。
- 已放好的块超过四个，BFS 状态数会爆，换成 IDA*，用「错位贴纸数 ÷ 4」剪枝。
- 第三层不值得搜。朝向和排列的组合有限，固定公式更快，也更容易讲清楚。

## 我是怎么走到这一步的

第一版是手写白十字。DF 位置那条棱，白色贴在 F 面，我写的插入是 `F D' F'`。测下来这块根本没动。

盯着置换表才想明白：`F` 和 `F'` 只转 F 层，`D'` 只转 D 层，整个序列不过是 `D'` 的共轭，只在 D 层里打转，没有一步把块送进 U 层。纯色贴纸上看不出来，因为四条 D 棱互换之后，画面还是「乱」的，很像成功。

改 BFS 之后，我写了个按阶段打印的诊断脚本。白十字四条边全对，白角四条里三条白面朝上、侧面颜色全错。查了半小时才发现 `_bfs_place` 的实参顺序传反了：它要的是「当前贴纸位置」，我传了「目标位置」，函数一进来就判断起点等于终点，返回空序列，白角那一段一步都没走。

修好参数，白角对了，第二层又不对：棱块进了正确的位置，两块颜色却互换了。原因是我按「面」去对应目标贴纸——FR 位置的第一张贴纸在 F 面，第二张在 R 面，但棱块待在 U 层时，颜色朝向不一定跟着面走。改成按颜色对应：F 色的贴纸去 F 面那个位置，R 色的去 R 面，翻转就消失了。

接下来不是错，是慢。把已放好的 8 块全部当成约束，只还原前两层要 116 秒。后来把中层改成只约束白十字的 4 条边，并把已放块超过 4 个的情况切到 IDA*，同一条打乱 2 秒级跑完。

现在的状态：前两层稳定，第三层的黄十字和 OLL 还会失败，正在改。

## 关键取舍

放弃了手写 case。它代码短、步数也短，但正确性得靠人肉穷举：12 个位置乘 2 种朝向，漏一个就是死循环。搜索版本宁可多走几十步，也不会漏。

放弃了全局最优。层先法本来就不是最短解，搜出来的一条解经常 500 步以上。要短解就得换 Kociemba 两步法，那是另一个量级的工作，不是这次的目标。

放弃了第三层也用搜索。那一层的块本来就少，朝向和排列的组合有限，固定公式比搜索更省事，出错时也更容易对着一层层打印去查。

## 可以直接抄的部分

贴纸置换用「拉模型」：`new_state[i] = old_state[perm[i]]`。逆置换就是反向移动，复合两次就是 180°。

```python
# 省略 MOVE_PERMS 里的具体表，只留生成逻辑
for face in ['U', 'D', 'L', 'R', 'F', 'B']:
    p = MOVE_PERMS[face]
    MOVE_PERMS[face + "'"] = invert(p)
    MOVE_PERMS[face + '2'] = compose(p, p)   # compose(a, b)[i] = a[b[i]]
```

自检用 sexy move 的阶：`R U R' U'` 连做 6 次必须回到原状。这条对不上，说明某张置换表的环写错了。

带约束的搜索核心，状态里同时带上目标块和已放好的块：

```python
from collections import deque

def place_one(current, target, placed, moves, sticker_map, max_depth=10):
    """current / target: 目标块的贴纸位置
       placed: [(贴纸列表, 目标列表), ...] 已放好的块"""
    queue = deque([(current, placed, [])])
    seen = {(tuple(current), tuple(tuple(p) for p, _ in placed))}
    while queue:
        cur, plc, path = queue.popleft()
        if tuple(cur) == tuple(target):
            return path
        for mv in moves:                       # 18 个基本动作
            if skip(mv, path[-1] if path else None):   # 同面连转 / 对面顺序重复
                continue
            m = sticker_map[mv]
            nxt = [m[s] for s in cur]
            np_ = [[m[s] for s in p] for p, _ in plc]
            if any(tuple(p) != tuple(t) for p, (_, t) in zip(np_, plc)):
                continue                       # 已放好的块被碰了
            if tuple(nxt) == tuple(target):
                return path + [mv]
            key = (tuple(nxt), tuple(tuple(p) for p in np_))
            if key not in seen and len(path) < max_depth:
                seen.add(key)
                queue.append((nxt, list(zip(np_, [t for _, t in plc])), path + [mv]))
    return None
```

两条剪枝就够用：同一面不连转（`U U'` 互相抵消），对面同时出现时只保留一个固定顺序（`U D` 和 `D U` 等价）。不加这两条，BFS 会多出几倍的无用状态。

已放块超过 4 个时改用 IDA*，启发式只数错位的贴纸：

```python
def h(cur, target, placed):
    wrong = sum(a != b for a, b in zip(cur, target))
    wrong += sum(a != b for p, t in placed for a, b in zip(p, t))
    return (wrong + 3) // 4   # 一步最多让 4 张贴纸归位
```

## 踩过的坑

**现象：白十字在部分打乱上死循环。**
原因：手写分支只覆盖了我想到的位置，DF 且白色朝前的 case 用 `F D' F'` 只是在 D 层循环。
解决：换成 BFS，不再枚举 case。
下次：「位置 × 朝向」的组合先算总数（12 × 2），再决定要不要手写。

**现象：白十字对，白角全错，求解步数还异常少。**
原因：`_bfs_place` 的实参顺序传反，函数以为起点就是终点，返回空序列。
解决：按阶段打印诊断；给搜索函数加一条「返回空序列时打印起点与终点」的日志。
下次：搜索返回空结果，先怀疑起点和终点搞反。

**现象：第二层棱块位置对，两块颜色互换。**
原因：按面而不是按颜色去对齐目标贴纸。
解决：按颜色映射，两个色各自对应自己那一面。
下次：位置和朝向是两件事，能拆开就不要混在一个条件里。

**现象：一次求解 116 秒。**
原因：8 个已放好的块全部作为约束，状态数指数增长。
解决：中层只约束白十字 4 条边，已放块超过 4 个切 IDA*。
下次：约束一多就换带启发式的搜索，别在 BFS 里硬扛。

## 收尾

这套写法只在 3×3 上验证过，前两层能稳定还原，第三层还在修。它适合正确性优先的场景：教学、演示、给别的语言做参照实现——我后面就打算照着这份逻辑写 Java 版。要短解就得上 Kociemba，那是另一条路，和这套代码不是一回事。
