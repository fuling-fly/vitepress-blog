# 把需求讲给 AI 的三个层次

![提示词示例封面](/images/cover-prompt.svg)

同一段需求，喂给同一个模型，写出来的东西质量能差三倍。差别几乎全在「你怎么描述」。

## 第一层：只说结果

> 帮我写一个博客页面。

模型只能按最常见的模板猜：标题、列表、页脚。能用，但肯定不是你想要的。这一层的典型症状是**返工三次还在改**。

## 第二层：补上边界

> 用 VitePress 的默认主题做一个博客首页，不要引入额外 UI 库，保持移动端可用。

边界一加上，模型就会放弃 Tailwind、放弃花哨动画，开始在既有约束里做设计。多数需求到这一层就够了。

| 要素 | 反例 | 正例 |
| --- | --- | --- |
| 技术约束 | 随便用 | 用 VitePress 默认主题 |
| 禁止项 | 无 | 不引入额外 UI 库 |
| 交付形态 | 做一下 | 给完整文件内容 |

## 第三层：写清验收标准

> 要求：① 首屏不出现横向滚动；② 构建零警告；③ 新增文章不需要改配置文件；④ 给出改动的完整文件列表。

验收标准让模型自己检查结果，而不是把「看起来差不多」丢给你。这一层最像写测试——先想清楚怎么判对错，再让它动手。

::: tip 一个可复用的句式
「做 X。约束是 A、B。完成后请逐条确认 ①②③ 是否满足，不满足就继续改。」
:::

## 我现在的习惯

1. 先用一句话说清目标；
2. 把它可能误解的点写成禁止项；
3. 最后补三条验收标准；
4. 让它自检一遍再交付。

第四步经常能捞回一两个明显的疏漏，成本几乎为零。
